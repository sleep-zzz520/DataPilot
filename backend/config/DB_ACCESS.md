# 数据库配置授权

升级后，旧数据库配置和新建配置都先由管理员访问。普通用户需要逐个配置授权。数据库配置里的默认标记只影响默认选中项。升级保留现有配置和历史会话，管理员需为仍应访问数据库的普通用户补发授权。

1. 管理员登录后，用 `GET /api/auth/users` 查用户 ID，用 `GET /api/config/db` 查配置 ID。
2. 用 `GET /api/config/db/{cfg_id}/grants` 查看配置的授权名单。
3. 用 `PUT /api/config/db/{cfg_id}/grants` 提交完整名单，例如 `{"user_ids":[12,27]}`。提交空数组可撤销该配置对所有普通用户的授权。编辑连接配置会保留原名单。授权变更会写入配置审计。

普通用户只能在列表看到获授权的配置。读取配置详情、查看表结构和发起聊天时，服务端都会检查同一个授权名单。已登录用户请求无权使用的配置时会收到 HTTP 404，流式聊天也会在发送 SSE 响应之前返回该状态。测试连接和管理授权需要管理员角色。管理员角色以当前账号记录为准，降级或注销后，原令牌在后续请求中按当前账号状态处理。

应用层授权以数据库连接配置为单位。每个连接账号在 MySQL 端应只拥有该配置所需的库表权限，并使用只读权限。授权撤销对后续请求生效，已经开始处理的请求和已保存的历史结果仍按原有流程处理。
